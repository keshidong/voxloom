# 移除 Voxloom 的 ASR 自动上下文

2026-11-24。桌面听写改为使用本轮录音、用户选择的语言和设置里的手动词汇。移除了为 ASR 读取前台窗口、输入框和聊天内容的路径，以及窗口摘要、自动关键词、相关设置和 Debug 上下文日志。[桌面听写入口](../../src/business/VoxloomDesktop/VoxloomFlow.swift)

## 为什么移除

- **提示文本可能变成转写结果。** 实际使用中，用户没说话时，转写出现了 App 自己附加的「按当前录音转写，结合背景辨认近音词，保留中英文术语的拼写。」本机回放也观察到，仅有底噪时，Qwen3-ASR 可能复述上下文摘要。当前版本已移除这句指令，并在解码前过滤静音、低底噪和很短的碰麦声。[Qwen3-ASR 录音检查](../../src/business/QwenASR/QwenASRRecognizer.swift)
- **已知正确的词有收益，窗口自动选词的收益还没有得到验证。** 从参考稿挑出的词已经确定出现在录音中。窗口文字则可能包含上一轮话题、侧栏文字或本轮不会说到的术语。正确词的评测结果不足以证明自动读取窗口能降低错误率。
- **手动词汇可以直接覆盖已知术语。** 用户可填写完整的人名、产品名或专业短语。Qwen3-ASR 的提示预算为 512 UTF-8 字节，App 按填写顺序取前面的词汇。移除自动路径也省去了每轮的窗口读取和摘要工作。[词汇传递和截断](../../src/business/Dictation/DictationSession.swift)

## 两轮全量对照

两轮都使用 Qwen3-ASR 1.7B MLX 4-bit 的自动语言模式，在同一批 1,965 段公开录音上比较。指令对照的两组共享同一背景，差别是是否追加旧指令。词汇对照从空提示开始，为录音加入最多两个参考稿中的正确词或短语，11 段混说保留空提示。两轮各自使用对应测试条件的基线。[FLEURS](https://huggingface.co/datasets/google/fleurs/tree/3c5cd38623376cb92bc769d5193891b564853276) · [ASCEND](https://huggingface.co/datasets/CAiRE/ASCEND) · [评分实现](../../src/business/QwenASR/Tests/AccuracyScoring/ASRAccuracy.swift)

| 分组 | 录音数 | 加入旧指令前后错误率 | 加入正确词汇前后错误率 |
| --- | ---: | ---: | ---: |
| 普通话 CER | 945 | 12.87% → 16.67% | 9.02% → 8.62% |
| 英文 WER | 647 | 4.26% → 4.18% | 4.03% → 3.72% |
| 中英混说 MER | 373 | 12.78% → 20.13% | 12.11% → 10.69% |

指令对照中，一段 4.9 秒的混说录音出现长串重复，复跑得到相同结果。两组都去掉该段后，加指令仍使混说错误率从 12.53% 上升到 14.02%。加正确词的对照中，混说的目标词命中率从 83.96% 升到 89.86%。

本机逐段结果保存在 `.build/reports/asr-instruction-ab/report.json` 和 `.build/reports/asr-vocabulary-ab/report.json`。
